# Compact UI V5 accessibility results

## Automated scope

The V5 Playwright audit runs `@axe-core/playwright` with WCAG 2 A/AA, WCAG 2.1 AA and WCAG 2.2 AA tags at 1920×1080, 1440×900, 1024×768 and 390×844.

Corrections made during the audit:

- darkened low-contrast Simple View header and row metadata;
- darkened Monthly KPI, target-denominator and evidence metadata;
- made scrollable Monthly, Trendlyne, Long Options and Simple View regions keyboard focusable and named;
- increased the OIIS active-checkbox hit target to 24×24 px;
- retained focusable/clickable information panels instead of hover-only explanations;
- retained colour-independent text for target, state and accounting semantics.

The 12 representative desktop page-family routes pass with zero serious or critical Axe violations and zero Axe timeouts after these corrections. The complete 55-route/four-viewport sweep has no outer overflow or feature-flag failure and is generated by `tools/playwright/compact-v5-audit.mjs`.

## Manual checks

- Tab reaches app navigation, filters, table sort/filter controls and inspectors.
- Enter opens interactive evidence rows.
- Escape behaviour remains owned by the existing canonical inspectors.
- Scrollable analytical regions expose a focus target and accessible label.
- Reduced-motion browser context is used for the screenshot audit.

Independent manual keyboard acceptance by the three production users remains pending; the checks above are the implementation-owner review and automated evidence, not a substitute for human UAT.

The synthetic local HTTPS audit cannot proxy WebSocket upgrades through Playwright route interception. REST evidence is live and canonical; WebSocket behaviour is covered by the existing deployed regression suite and is recorded separately from accessibility results.
