# MIGRATION SYSTEM         #
############################
Implement a minimal, robust migration framework:

1) A table schema_migrations under the configured schema:
   - version TEXT PRIMARY KEY
   - applied_at TIMESTAMPTZ NOT NULL DEFAULT now()
   - checksum TEXT NOT NULL
2) Each migration step has:
   - version string e.g. "001_init"
   - checksum (sha256 of the SQL string)
   - SQL statements (single multi-statement string)
3) On migrate:
   - read applied versions
   - apply missing migrations in order
   - verify checksum if version already applied (fail hard if mismatch to prevent drift)

Use a Postgres advisory lock around migrations:
- SELECT pg_advisory_lock(hashtext(schema || ':migrate'));
- Ensure unlock in defer.

All migrations must be idempotent where possible (CREATE TABLE IF NOT EXISTS, CREATE INDEX IF NOT EXISTS, ALTER TABLE ADD COLUMN IF NOT EXISTS).

# CLEANUP / RETENTION       #
############################
Implement internal/store/cleanup.go:

- collector --db-cleanup-only runs cleanup once and exits.
- Normal run: if retention.enable is true, run cleanup once at startup and then once daily at a quiet time (e.g., 03:00 IST) OR every 6 hours; make it configurable later if needed.

Retention rules:
- bars_1m: keep last retention.bars_1m_days
- quote_snapshots: keep last retention.quote_snapshots_days
- option_greeks: keep last retention.option_greeks_days
- instruments: keep forever by default

Cleanup method:
1) Acquire advisory lock (hashtext(schema || ':cleanup')).
2) Compute cutoff timestamps in UTC based on IST-now minus N days.
3) If partitioned:
   - identify partitions with range end <= cutoff
   - if dry_run: log partitions that would be dropped
   - else: DROP TABLE schema.partition_name
4) If not partitioned:
   - DELETE FROM table WHERE ts < cutoff (batched deletes by LIMIT, loop)
5) After deletion:
   - ANALYZE affected tables
6) Release lock.

Log:
- how many partitions dropped
- estimated rows deleted (if available)
- durations per step
