# Home and screener live-refresh repair — 20 September 2026

## Scope

This is a presentation and refresh-lifecycle repair for the authenticated Home
surfaces and `/strategy/scalper-dashboard`. It does not change MWHD, Monthly,
OIIS, 3Month calculations, rankings, source values, collectors, orders or
alerts generated by trading strategies.

## Cause found

- Home treated any overview query error as a fatal initial-load error. A failed
  background poll could therefore replace a hydrated market canvas with the
  full error state even though React Query still held a valid prior snapshot.
- The current-month screener hid its table whenever `isError` became true,
  including background refresh failures with valid cached rows.
- The progression API deliberately serves the last cached response while its
  one-minute background regeneration runs. If regeneration repeatedly fails,
  the HTTP response can remain successful while the payload `generatedAt`
  stops advancing. The UI previously had no explicit detector for this state.

There is no timer-driven `window.location.reload` in these screens. React Query
polls Home every 10 seconds and the progression screener every 60 seconds.

## Repair

- Hydrated Home and screener content remain mounted during background errors.
- `LiveRefreshStatus` reports each source's last successful timestamp and
  cadence, shows in-place refresh activity, and emits an accessible alert when
  a request fails or a server-generated progression snapshot is more than
  three refresh intervals late.
- Error and stale states explicitly say that the last good data is retained and
  provide an in-place Retry action.
- Progression polling now explicitly revalidates after window focus and network
  reconnect, while remaining paused in a hidden background tab.
- The Home trading drawer and MWHD matrix retain cached ranks and disclose a
  refresh failure instead of calling them unavailable.

## Validation contract

Unit coverage verifies fresh, stale, background-error and no-data states.
`tools/playwright/home-screener-live-refresh.mjs` injects read-only HTTP 503
responses after initial hydration and verifies that Home and the screener:

1. show an accessible refresh alert;
2. retain the last good canvas/table and row count;
3. do not navigate, reload or remount the main data surface;
4. recover in place after Retry.

Repository checks required before release remain the web/API typechecks, full
unit suites, production builds and canonical repository gate. Browser evidence
is stored outside Git under the configured Playwright output directory.
