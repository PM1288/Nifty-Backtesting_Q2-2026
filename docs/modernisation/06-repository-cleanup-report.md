## Exact duplicates requiring ownership decisions

- Two pairs of delivery DOCX files are byte-identical copies with `(1)` names.
  Keep one canonical document and archive the duplicate only after reference
  search and document-owner confirmation.
- StratLab deployment SQL mirrors package migrations byte-for-byte for several

  archive an applied migration merely because hashes match.
- Catalogue/test-wave JSON appears both in catalogue and workload directories.
  Runtime call-site ownership must determine whether this is generated or an

- Two large historical `decisions.csv.gz` outputs are identical in content but
  belong to different run IDs. Result identity and manifests must be checked
  before deduplication.

## Build and dependency reproducibility defect

The frontend repository includes both `package-lock.json` and `pnpm-lock.yaml`.
Root scripts invoke `corepack pnpm`, but the production Dockerfile copies the npm
lock and runs `npm ci`. On the audited host `corepack` is absent, causing the root
`npm run typecheck/build` wrappers to fail, while direct npm workspace commands
pass. The recommended isolated fix is to declare npm/package-lock authoritative
and update root scripts, or deliberately migrate the Dockerfile and CI to pnpm;
do not retain contradictory tooling.

## Sensitive material

Runtime `.env` values were not printed or copied. Tracked environment files
under `compose/env/` require a value-level secret scan before release. No secret
scanner binary is installed on the host at capture; use a pinned CI/container
scanner rather than installing an untracked global dependency during audit.

## Controlled archive plan

If legacy source/config is proven unused, move it with `git mv` into:

```text
archive/legacy/2026-08-09/
  README.md
  manifest.csv
  old-services/
  old-compose/
  old-scripts/
  old-config/
  old-docs/
```

The manifest columns are `original_path`, `archived_path`, `classification`,
`reason`, `last_known_reference`, `replacement_path`, `risk_if_restored`,
`archive_date` and `eligible_for_future_deletion`. The archive must be excluded
from Docker contexts, imports, package discovery, lint and deployment.

## Required gates before moving files

1. Search static/dynamic imports, Compose, Nginx, cron/systemd and CI references.
2. Record the runtime consumer or prove absence through logs/call sites.
3. Run build, contract and replay tests.
4. Move a small batch with `git mv` and update the manifest.
5. Rerun the same tests and clean-checkout build.
6. Never archive applied migrations, backup/restore tooling, SmartAPI mappings,
   strategy definitions tied to results, or audit evidence.
